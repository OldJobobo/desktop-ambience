# Desktop Ambience v0.6.0 Release Evidence

Date: 2026-08-20

## Result

Phase 7 and the complete Phase 6 release matrix passed. Version 0.6.0 adds Tactical Grid as the ninth ordered renderer, with pointer-driven parallax, full-screen targeting guides, four reticle styles, configurable theme roles, and reduced-motion behavior. It also fixes shared cursor injection in the live panel and keeps Dust Motes pointer influence valid across negative and adjacent monitor coordinates.

## Tactical Grid contract

`tacticalGrid` is registered through `services/EffectRegistry.js` and participates in the existing normalized settings, generic settings editor, lazy stack loading, front-to-back ordering, theme adaptation, foreground/background presentation, fullscreen suppression, and per-output lifecycle.

The renderer owns no process, file reader, window, or input surface. One panel-owned `CursorTracker` supplies raw coordinates for output ownership and eased display coordinates for reticle and parallax motion. Half-open output bounds ensure that a pointer on a shared monitor edge belongs to exactly one renderer.

Existing settings documents receive normalized Tactical Grid defaults without adding it to their active stack. Users opt in through **Add Effect**.

## Measured result

The isolated Phase 7 harness profiled fresh Quickshell processes with temporary XDG homes and reversible headless outputs.

| Measurement | 1 output | 3 outputs |
| --- | ---: | ---: |
| Tactical Grid CPU | 3.50% | 3.50% |
| Mean frame callback | 16.60 ms | 16.45 ms |
| Maximum frame callback | 17.19 ms | 17.38 ms |
| Frames over 20 ms | 0 | 0 |
| Cursor launches per four-second sample | 34 | 34 |
| Peak RSS | 273.2 MiB | 283.3 MiB |

The cursor launch count remained constant across output count, confirming that Tactical Grid shares one sampler rather than creating one process per renderer.

## Residual risks

- Tactical Grid uses the shared `hyprctl cursorpos -j` sampler at a 60 ms interval while pointer visuals are required. This avoids per-output multiplication but still launches short-lived subprocesses.
- CPU and frame measurements are machine-local, directional samples rather than universal performance targets.
- Theme-role choices depend on the active Omarchy palette; extended Base16 roles retain the shared adapter's last-valid-palette behavior during theme replacement.
